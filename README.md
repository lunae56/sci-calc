# 科学计算器（控制台版）

纯 C++ 标准库实现的表达式计算器。**零外部依赖**，不使用 `vector` / `map` 等容器，
解析器是手写的递归下降（recursive descent），**不用任何第三方表达式库**。

已用 **Visual Studio 2022（MSVC 14.44，C++17）** 编译，`/W4` 零警告；
93 个用例全部通过（见下方「自测」）。

---

## 一、编译

只需要一个源文件。任选一个编译器：

```bash
# MSVC（VS2022 / VS2019）
cl /std:c++17 /utf-8 /W4 /O2 /EHsc scientific_calc.cpp

# g++ / clang++（Linux、macOS、MinGW）
g++ -std=c++17 -O2 -Wall -Wextra -o sci_calc scientific_calc.cpp
```

Windows 下装了 VS2022 的话，直接双击 `build.bat` 即可（里面已写好 `vcvarsall.bat` 和编译参数）。

> `/utf-8` 告诉 MSVC 源文件是 UTF-8，这样源码里可以直接写 `√`、`π` 这类字符。
> 用 g++ / clang++ 默认就是 UTF-8，不用额外加参数。

## 二、运行

```bash
./sci_calc                       # 交互模式（默认角度制）
./sci_calc "2+3*4"               # 算一个表达式就退出
./sci_calc --rad "sin(pi/2)"     # 弧度模式
./sci_calc --deg "sin(30)"       # 角度模式
./sci_calc --batch expr.txt      # 批处理：从文件逐行读表达式，一行一个结果
./sci_calc --help                # 帮助
```

### 交互模式

```
deg> 2+3*4
= 14
deg> sqrt(2)
= 1.41421356237
deg> sin(30)
= 0.5
deg> plot sin(x) 0 360 60       # 终端里画函数图像
deg> rad
已切换到弧度制
rad> sin(pi/2)
= 1
rad> quit
```

### 批处理模式

`expr.txt`：

```
# 井号开头是注释，空行忽略
1+2*3
sqrt(2)
2^10
√25
1/0
```

运行 `sci_calc --batch expr.txt`：

```
7
1.41421356237
1024
5
ERROR: 除以零
```

一行输入对应一行输出，出错时该行输出 `ERROR: ...`。方便写脚本批量验证，
也避免了 shell 传参破坏 `√`、`π` 这类多字节字符。文件里同样可以用 `deg` / `rad` 切换。

## 三、支持的内容

| 类别 | 内容 |
| --- | --- |
| 运算符 | `+` `-` `*` `/` `%`（取模） `^`（乘方） `(` `)` |
| 一元 | `-x` 取负、`+x` 保留符号 |
| 函数 | `sqrt` `sin` `cos` `tan` `asin` `acos` `atan` `ln` `log`(以 10 为底) `abs` `exp` `floor` `ceil` `round` |
| 简写 | `√x` 等价于 `sqrt(x)`（UTF-8 三字节，解析器手写识别） |
| 常量 | `pi` / `PI` / `π`、`e` |
| 数字 | `123` `3.14` `.5` `1e5` `2.5E-3` |
| 角度单位 | 角度制（默认）/ 弧度制，命令 `deg` / `rad` 切换 |
| 附加 | `plot 表达式 起点 终点 [采样点数]`，用字符在终端画函数图像 |

### 优先级与结合性

从低到高：`+ -` → `* / %` → 一元 `+ -` → `^` → 括号 / 函数。

- `^` 是**右结合**：`2^3^2` = `2^(3^2)` = 512
- 一元负号优先级**低于**乘方：`-2^2` = `-(2^2)` = -4
- 负指数可以直接写：`2^-3` = 0.125
- 函数名和常量**不区分大小写**：`SQRT(9)`、`PI` 都可以

## 四、错误处理

所有错误都会给出说明**并指出出错位置**（下面画 `^`）：

| 情况 | 示例输入 | 提示 |
| --- | --- | --- |
| 除零 | `1/0` | 除以零 |
| 对零取模 | `5%0` | 对零取模 |
| 非法字符 | `1+@` | 非法字符 '@' |
| 括号不匹配 | `(1+2` | 缺少右括号 ')' |
| 多余右括号 | `1+2)` | 多余的内容 ')' |
| 缺操作数 | `1+` | 表达式意外结束，缺少操作数 |
| 未知名称 | `foo(1)` | 未知的名称 'foo' |
| 函数缺括号 | `sqrt 2` | 函数 sqrt 后面需要括号，例如 sqrt(2) |
| 函数缺参数 | `sin()` | 函数 sin 缺少参数，例如 sin(2) |
| 负数开平方 | `sqrt(-1)` | 函数 sqrt 在 x=-1 处无定义（定义域错误） |
| 定义域错误 | `asin(2)` | 函数 asin 在 x=2 处无定义（定义域错误） |
| 乘方溢出 | `9^9^9` | 乘方结果溢出 |
| 结果非实数 | `(-8)^0.5` | 负数底数配非整数指数，结果不是实数 |
| 0 的负次幂 | `0^-1` | 0 的负数次幂（相当于除以零） |
| 数字后接字母 | `2pi`、`1e` | 数字 2 后面不能直接接 'p'，请加运算符 |

命令行模式下：正常退出码 0，表达式出错为 1，参数错误为 2；批处理模式下有任一错误行则为 1。

## 五、实现要点

**解析流程**：一次扫描，不预先做完整的词法分析，而是在递归下降过程中按需取 token。
文法一共五层：

```
expr    := term  { ("+" | "-") term }
term    := unary { ("*" | "/" | "%") unary }
unary   := ("+" | "-") unary | power
power   := primary [ "^" unary ]        // 右侧递归 → 右结合
primary := number | "(" expr ")" | name "(" expr ")" | "√" unary | name
```

**不用容器的做法**：
- 函数表是 `const FnEntry kFunctions[]` 固定数组 + 线性查找
- `plot` 的采样点用固定上限的栈上数组（`double ys[200]`）
- 字符画布是 `char canvas[21][201]` 二维数组
- 只用到 `std::string` 本身来存输入和拼错误信息

**错误传递**：内部用 `CalcError` 异常，在最外层（`evaluate`）统一捕获并转成
`ParseResult`（成功标志 + 值 / 错误），这样交互模式下一次出错不会退出程序。

**UTF-8 处理**：`√` 和 `π` 都是多字节字符。解析器按 UTF-8 首字节判断字符长度
（`utf8Len`），报错信息里用 `utf8CharAt` 取**完整**字符——否则像 `2π` 这种错误提示
会因为只截了一个字节而显示成乱码。

**中文乱码的处理**（Windows 专有，见源码里的「输出层」一节）：

源码里的中文在 exe 里是 UTF-8 字节，而 Windows 中文系统的控制台默认代码页是
936(GBK)，它按 GBK 解读 UTF-8 就会显示成 `閿欒: 闄や互闆` 这种乱码。

解决办法是**写到控制台时先转换编码**：用 `GetConsoleOutputCP()` 取当前控制台代码页，
把 UTF-8 转成该代码页再输出（`MultiByteToWideChar` → `WideCharToMultiByte`）。

同时用 `GetConsoleMode` 判断 stdout 是不是真控制台：
- **是控制台** → 转成控制台代码页再写，任何代码页下都显示正常
- **是文件/管道** → 保持原始 UTF-8，这样重定向出来的文件仍是标准 UTF-8，不会污染

已验证：代码页 936 下写「错误」，控制台实际存下的码点是 `U+9519 U+8BEF`（正确）；
不转换则存成 `U+95BF U+6B12 U+E1E4`（乱码）。

### 中文仍然显示不正常？

如果看到的是**方块或问号**（不是乱码），那是控制台字体的问题，不是编码问题：
在标题栏右键 →「属性」→「字体」，选 **Consolas** 或 **Lucida Console** 这类 TrueType
字体即可（点阵字体不含中文字形）。Windows 10 之后的控制台默认就是 TrueType，一般不用管。

## 六、自测

`tests/run_tests.ps1` 里有 93 个用例，覆盖基本运算、优先级与结合性、全部函数、
UTF-8 字符、数字字面量、20 种错误情况、角度单位切换。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_tests.ps1
```

它是用 `--batch` 模式跑的：用例写进 UTF-8 文件，逐行比对输出。

> 注意：**不要用命令行参数传 `√` / `π` 做测试**。Windows PowerShell 5.1 传参时会把
> 这些字符转成系统代码页编码，导致程序收到乱码——这是 shell 的问题，不是程序的。
> 用 `--batch` 或交互模式输入就没这个问题。

想开更严格的编译检查：

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -o sci_calc scientific_calc.cpp
```
